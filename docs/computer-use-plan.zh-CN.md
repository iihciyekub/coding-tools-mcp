# ChatGPT 桌面操作能力实施方案

日期：2026-09-21。状态：第一版作为 Desktop 0.3.34 的可选预览功能交付，本机 MCP 和正式签名 helper 验证通过；真实 ChatGPT 对话和全新安装后的系统权限授权体验待验收。

接口、权限规则与验收清单统一以 [Computer use v1 spec](computer-use-spec.md) 为准。本页说明产品职责、实施阶段和使用路径，不另行维护接口参数副本。

## 产品职责

```text
ChatGPT 聊天（理解任务、调用工具、继续推理）
  ↓ 现有 OAuth HTTPS 连接
本机 Python MCP runtime（接口、授权校验、会话、操作回执）
  ↓ 私有 stdio 协议
桌面 App 随包提供的原生 helper（macOS 窗口、辅助功能、截图）
  ↓
用户已批准的应用
```

桌面端负责安装 helper、启动服务、建立隧道、引导系统授权、处理应用访问申请和立即停止。核心 runtime 可独立运行，无需依赖 Codex App；不需要在我们的云端部署能直接操作用户桌面的进程。

“后台操作”表示支持的控件可以通过辅助功能接口直接操作。它不意味着退出聊天后模型会持续自主推理，也不意味着所有应用的全部控件都能操作。

## 第一版范围

- 支持已运行的 macOS 应用；窗口截图需要 macOS 14 或更新版本。
- 提供应用枚举、会话申请/查询/启动/停止、窗口枚举、截图与元素树、控件按下/文本赋值、条件等待。
- 默认关闭。启用后，十个工具直接暴露给 LLM，并加入工具发现目录；截图通过 MCP image content 返回。
- 人工批准绑定应用实例、观察或控制范围、有效期。Full Access 不自动批准应用会话。
- 动作引用来自实际观察；拒绝过期、已使用或发生变化的快照。重复调用通过回执去重，不盲目重做结果未知的动作。
- 桌面与 LLM 读取同一份授权/会话状态；停止后拒绝后续和排队中的动作。
- Windows/Linux 保留现有编程功能，原生应用控制明确返回不支持。全局键鼠、应用启动、浏览器专用接口、持久应用授权列为后续扩展。

桌面的人类授权入口不会暴露为 LLM 自行批准的工具。除此之外，本期原生观察与操作能力均有对应 MCP 接口；映射见 spec。

## 实施与验收

| 阶段 | 当前状态 | 证据与下一步 |
| --- | --- | --- |
| 统一接口契约 | 已实现 | 单一工具/schema 定义，注册、发现、注解、结果渲染和文档对齐检查 |
| 授权和会话 | 已实现 | 一次性批准、只读限制、到期、撤销、跨工作区占用、动作回执测试 |
| 原生观察和操作 | 本地验证通过 | 临时测试 App 完成截图、后台文本赋值、按钮按下和结果验证 |
| 桌面集成 | 已实现 | 开关、系统权限入口、应用身份/范围展示、批准/拒绝、停止、helper 打包 |
| MCP 传输 | 本地验证通过 | HTTP 工具目录、图片只返回一次、操作后继续观察 |
| ChatGPT 实际聊天 | 待验收 | 连接测试服务后验证图片理解、多步工具调用及刷新工具目录 |
| 正式安装包 | 按发布契约验收 | 已验证 Developer ID 签名 helper；全新安装后的权限归属、升级、重启与重连仍需用户环境验收 |

## 开发构建和使用路径

1. 开发构建运行 `npm run build:bundle`；完整测试 app 使用 `npm run tauri build -- --debug --bundles app`。两条命令均在 `apps/desktop-client` 执行。
2. 在构建后的桌面端选择工作区，进入“应用操作”，停止正在运行的服务后开启功能。
3. 使用页面中的辅助功能、屏幕录制设置入口完成 macOS 授权，再启动服务。工具不会代替用户授予系统权限。
4. 在 ChatGPT 连接该服务并刷新工具目录。开启本机服务本身不会自动把工具加入所有聊天。
5. 让模型先调用 `computer_status` 和 `app_list`，为目标应用申请访问，在桌面端检查应用名称、路径、进程、范围和时长后批准。
6. 模型启动获批会话，观察窗口，操作控件，再通过观察验证结果；完成后停止。用户也可在桌面端随时停止。

已注册工具的精确参数以连接的 `tools/list` 为准，避免使用历史 `app_*` 参数。

## 回归与限制

测试入口和本次记录集中在 [spec](computer-use-spec.md)。核心保持默认 28 个工具不变，只有明确开启应用操作才新增十个工具。开发构建可继承启动环境的系统权限，不能据此推断正式签名安装后的授权体验。

同一工作区仍是共享信任域，应用授权不构成对 Full Access shell 的系统隔离。截图和窗口文本会传给连接的 AI；原生工具不运行工作区 hooks，日志不记录输入正文或界面内容。详见 [安全边界](security-boundary.md)。

后续扩展应按能力逐项交付，不先暴露占位工具：应用启动与菜单/滚动、应用专用 API、浏览器、Windows、持久授权、多客户端隔离，以及独立于聊天会话的任务调度。
